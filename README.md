# VRG Прокси

Раздача HTTP/SOCKS-прокси с Android-телефона на базе ядра [mihomo](https://github.com/MetaCubeX/mihomo).
Замена Every Proxy для сценария «дал ребёнку Quest 3, надо чтобы магазин Meta заработал».

Телефон подключается к вашей подписке и превращается в прокси-сервер для
локальной сети. Quest, ноутбук, телевизор — любой клиент, умеющий HTTP-прокси,
получает доступ через ваш сервер, ничего на нём не устанавливая.

## Что видит пользователь

Один экран: большая кнопка, под ней адрес и порт, которые надо вбить в
настройках Wi-Fi на Quest, статистика и выбор сервера чипами. Ниже — кнопка
«Как подключить Quest 3» с пошаговой инструкцией. Всё остальное (подписка,
порт, режим маршрутизации, пароль) — под «Дополнительно».

Инструкция разделена на два пути, потому что они не совпадают:

- **Новый шлем.** Прокси вписывается прямо при первом подключении к Wi-Fi:
  ввести пароль сети, но не нажимать «Подключиться», открыть расширенные
  настройки и задать прокси там. Без этого шлем не пройдёт активацию.
- **Уже настроенный.** Настройки → Wi-Fi → своя сеть → расширенные настройки.

## Сборка

Нужны JDK 17+ и Android SDK (compileSdk 35, build-tools 35).

```bash
./gradlew assembleRelease
```

APK окажется в `app/build/outputs/apk/release/app-release.apk`.

Подпись берётся из `keystore.properties` в корне проекта (`storeFile`,
`storePassword`, `keyAlias`, `keyPassword`). Файл и сам `.jks` — в `.gitignore`.
Если их нет, релиз соберётся с отладочной подписью.

**Ключ подписи надо забэкапить.** Потеряешь `vrgproxy-release.jks` — обновить
уже установленное у людей приложение будет нечем, только переустановка с нуля.

Путь к SDK берётся из `local.properties` (`sdk.dir=...`) — файл не в репозитории,
создайте свой.

### Ядро

Ядро в репозитории не лежит — собери его перед первой сборкой:

```bash
ANDROID_NDK=~/Library/Android/sdk/ndk/29.0.14206865 tools/build_core.sh
```

Скрипт склонирует mihomo и положит бинарники в
`app/src/main/jniLibs/{arm64-v8a,armeabi-v7a}/libmihomo.so`.

Это исполняемые файлы, а не библиотеки. Имя с расширением `.so` выбрано
специально: `nativeLibraryDir` — единственный каталог приложения, из которого
Android разрешает запускать файлы (W^X). Скопировать бинарь в `filesDir` и
сделать `chmod +x` начиная с Android 10 не работает. По той же причине в
`app/build.gradle.kts` включён `useLegacyPackaging = true` — иначе ядро
останется сжатым внутри APK и запускать будет нечего.

**Нужен NDK и `CGO_ENABLED=1`.** Соблазнительно собрать без него как
`GOOS=linux GOARCH=arm` — оно даже соберётся и запустится, но Go в linux-сборке
ищет корневые сертификаты в `/etc/ssl/certs`, которых на Android нет. Всё TLS
наружу падает с `x509: certificate signed by unknown authority`: умирает
DNS-over-TLS, за ним не качается подписка. Читать системные сертификаты Android
умеет только `GOOS=android`.

### Релизы через GitHub Actions

`.github/workflows/release.yml` по тегу `v*` собирает ядро, собирает три APK
(arm64, armv7, универсальный), подписывает и прикладывает к релизу.

Ключ подписи хранится в секретах репозитория, а не в коде:
`KEYSTORE_BASE64` (файл `.jks`, закодированный `base64 -i vrgproxy-release.jks | tr -d '\n'`),
`KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.

## Как это работает

1. Конфиг лежит в `app/src/main/assets/base_config.yaml` — правила, DNS,
   маршрутизация. Пользователь его не видит и не правит.
2. `ConfigBuilder` подставляет в него ссылку, порт, пароль и финальное правило.
   Подписку он **не качает и не парсит**: её тянет само ядро через
   `proxy-providers`, поэтому приложению всё равно, YAML там, base64 или что-то
   ещё — форматы разбирает mihomo.
3. Ядро стартует отдельным процессом: `libmihomo.so -d <filesDir>/mihomo -f config.yaml`.
4. Приложение ждёт, пока ответит RESTful API на `127.0.0.1:9090`, и только после
   этого показывает адрес — чтобы пользователь не вбивал его в Quest раньше времени.
5. Дальше управление идёт через тот же API: выбор сервера, трафик, пинг.

Список серверов берётся из `/providers/proxies/subscription`, а **не** из группы.
Пока подписка не скачана, группа пуста и ядро подставляет в неё заглушку
`COMPATIBLE` — если спрашивать группу, эту заглушку легко принять за настоящий
сервер и показать её пользователю.

Имена нод подставляются в путь URL через `encodePathSegment`, а не голым
`URLEncoder.encode`: тот кодирует пробел как `+`, что в пути означает буквальный
плюс, и ядро не находит ноду вроде `Finland - TCP`. Ломало и пинг, и
переключение серверов.

Кнопка «Проверить» дёргает `/group/{name}/delay` — ядро меряет все серверы разом.
Не ответившие остаются в списке с пометкой, а не исчезают: так видно, что сервер
лежит, а не что его не проверяли.

`global-ua` зафиксирован (`clash.meta/1.19.0`). По умолчанию ядро шлёт
`clash.meta/<версия сборки>`, а панели раздают конфиг по User-Agent — не хочется,
чтобы поведение поехало при обновлении ядра.

Клиенты считаются по уникальным `sourceIP` из `/connections` с памятью в минуту.
Считать сами соединения нельзя — короткий запрос успевает закрыться между
опросами, и пользователь видит «клиентов: 0» при работающем клиенте.

### Что правится в конфиге и зачем

| Ключ | Значение | Причина |
|---|---|---|
| `allow-lan` | `true` | Без него ядро слушает только `127.0.0.1`, и Quest получает connection refused |
| `bind-address` | `*` | Слушать все интерфейсы, а не один |
| `lan-allowed-ips` | `0.0.0.0/0`, `::/0` | Пускать любого клиента из локальной сети |
| `mixed-port` | из настроек | HTTP и SOCKS5 на одном порту |
| `redir-port`, `tproxy-port`, `tun` | удаляются | Требуют root и iptables, на телефоне бесполезны |
| `enable-process`, `find-process-mode` | `false` / `off` | Соединения приходят с чужого устройства, владельца процесса определить нельзя; поиск в `/proc` — чистые потери |
| правила `PROCESS-NAME`, `PROCESS-PATH` | вырезаются | Не сработают никогда по той же причине |
| `dns.enhanced-mode` | `redir-host` | `fake-ip` ломает обычный HTTP/SOCKS-вход: клиенту некому отдавать поддельные адреса |
| `MATCH` | группа прокси или `DIRECT` | Переключатель «Весь трафик через сервер» в настройках |
| `external-controller` | `127.0.0.1:9090` + `secret` | Управление ядром только с самого телефона |
| `profile.store-selected` | `false` | Выбор сервера ставит приложение через API; запомненный ядром выбор только мешает |

Порт по умолчанию 7890. Ниже 1024 Android без root не разрешает — интерфейс
это ограничивает.

### Удержание в живых

- Foreground-сервис с постоянным уведомлением — иначе система убивает процесс
  через несколько минут и загрузка в Quest обрывается.
- `WifiLock` в режиме `WIFI_MODE_FULL_HIGH_PERF` — иначе Wi-Fi засыпает.
- `PARTIAL_WAKE_LOCK` — иначе Doze рвёт долгие соединения.

## Базовый конфиг

`app/src/main/assets/base_config.yaml` собирается из шаблона Remnawave
(`path/to/vrgMihomo.json`) скриптом:

```bash
python3 tools/build_base_config.py path/to/vrgMihomo.json app/src/main/assets/base_config.yaml
```

Правил менять руками в assets не надо — правь шаблон и перегенерируй.
Скрипт выкидывает `proxies` (их даёт провайдер), правила по процессам и всё
десктопное, а взамен ставит LAN-режим.

Сам шаблон тоже подправлен: добавлены `allow-lan`/`bind-address`, а `MATCH,DIRECT`
заменён на группу `FINAL` (по умолчанию `DIRECT`, так что для ПК поведение
не изменилось).

## Ограничения

- Клиент должен уметь HTTP-прокси. Quest умеет — в настройках Wi-Fi.
- Трафик между телефоном и клиентом внутри локальной сети не шифруется.
  В чужой сети включайте логин и пароль в «Дополнительно».
